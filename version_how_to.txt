How to release a new version number

Version pattern: "Major Version"."Minor Version"."Patch Version"

How to determine the new version number:
- Increase the major version only when there are very big changes in software and/or hardware (e.g. breaking changes, major architectural rework).
- Increase the minor version for new features or larger additions that remain backward compatible.
- Set the patch version to 0 when the major or minor version has been increased.
- Increase the patch version in every other case when you want to release a new version number (e.g. bug fixes, small changes).

Describe your changes:
Put a new version chapter in CHANGELOG.md at the beginning of the file, e.g. 3.2.3. Describe all changes since the last version number there.

Places where the version number has to be changed:
version.h
escam/escam.pro
escam_setup/escam_setup.vdproj

To change the version number in escam_setup.vdproj, click on the project escam_setup in the "Solution Explorer" (top right) in Visual Studio. Then change "version" in the properties (bottom right). A window will appear asking whether to change the product code. Click "Yes" to accept.

Optional:
After committing the version number change (best practice is to do this in its own commit), tag the commit with its version number, e.g.:

git tag 3.2.3

Push the tag to the remote repositories:

git push --tags
git push --tags github
